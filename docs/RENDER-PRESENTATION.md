# Free Render presentation deployment

This branch deploys a separate sample-only environment. It never copies or connects to the local employee database. Do not import real employee records into this preview.

## Recommended: Blueprint

In Render choose New > Blueprint, select ZeccDigi/HRIS-SYSTEM, and select branch pre-deployment. The render.yaml file creates one free Docker web service and one separate free PostgreSQL database in Singapore. Confirm both plans say Free. Set PRESENTATION_PASSWORD to a private password of at least 12 characters. No demo password is committed to Git. APP_KEY_SEED is generated by Render; keep it unchanged for the lifetime of the demo database.

## If using the Web Service form

Select branch pre-deployment, runtime Docker, region Singapore, root directory blank, Dockerfile path ./Dockerfile and plan Free. Docker supplies its own build and start commands. Create a separate Free Render Postgres database in Singapore. Add its Internal Database URL as the web service's DB_URL secret. Use the environment variables in render.yaml; APP_KEY_SEED must be a generated stable secret, and PRESENTATION_PASSWORD must be your private password (12+ characters). Set the health check to /up.

## Accounts

The first boot creates demo.admin@dmw.gov.ph, demo.hrstaff@dmw.gov.ph, demo.chief@dmw.gov.ph, demo.regionaldirector@dmw.gov.ph, demo.recordofficer@dmw.gov.ph and demo.employee@dmw.gov.ph. All initially use PRESENTATION_PASSWORD. The initializer preserves existing demo records and does not reset passwords on subsequent starts. It refuses to seed any pre-existing database that lacks the presentation initialization marker. It does not run DatabaseSeeder or its fixed development passwords.

## Data and uploads

Database data remains in the separate Render Postgres instance across web-service restarts. Demo attachments, signatures and profile photos are mirrored into encrypted database rows as part of successful write requests, and restored to their respective local disks before the next web start. Private files remain private; the existing document access controls continue to apply. This small-file presentation mechanism is disabled outside presentation mode and is not a production object-storage design. Uploaded files must be at most 20 MB. The application key must remain stable to decrypt these files.

Render Free sleeps after inactivity, does not provide persistent disks, and its Free Postgres expires after 30 days. No automatic cloud backups are included. Use sample records and export anything needed before expiry. Source: https://render.com/docs/free

## Email and kiosk limitations

MAIL_MAILER=disabled deliberately reports unavailable delivery instead of silently logging OTPs or claiming email was sent. The pre-verified demo accounts can log in without email. Real email/OTP presentation needs an email API service configured separately; Render Free blocks SMTP ports. The local kiosk still uses the local MySQL database. It does not automatically connect to this PostgreSQL demo, and must not be pointed at it as a MySQL connection. A hosted-kiosk API integration remains separate work.

## Verification after deployment

Wait for Live, open the HTTPS Render URL, sign in with a demo account, check the Dashboard and role menus, make a sample file upload, and verify persistence after a manual restart. Test PDS PDF export; Chromium is included in the image. A free instance may be slow to wake and has limited memory, so avoid simultaneous large PDF exports during the presentation. Do not configure a paid worker, disk or database for this free setup.
